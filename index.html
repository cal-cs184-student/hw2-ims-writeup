Overview

This assignment combines parametric modeling and triangle-mesh processing. I implemented de Casteljau evaluation for Bézier curves and tensor-product Bézier surfaces, area-weighted vertex normals, half-edge edge flips and splits, and Loop subdivision. I also extended edge splitting and Loop subdivision to meshes with open boundaries, and implemented an additional √3 subdivision scheme for closed triangle meshes.

The main conceptual connection is that smooth geometric models can be described either by control points or by a polygon mesh that is gradually refined. Bézier evaluation uses repeated interpolation; mesh processing instead relies on local connectivity and weighted averages. Testing the teapot, cube, and open two-triangle mesh showed how correct half-edge relationships are essential to changing topology without creating holes.

Section I: Bézier Curves and Surfaces

Part 1: Bézier Curves with 1D de Casteljau Subdivision

De Casteljau's algorithm evaluates a Bézier curve by recursively interpolating neighboring control points at a parameter t between 0 and 1. Each new level has one fewer point, with the recurrence:

Pi(k+1) = (1 − t) Pi(k) + t Pi+1(k).

In BezierCurve::evaluateStep, I loop over consecutive pairs of points, compute their linear interpolations, and return the resulting vector. The GUI calls this function repeatedly. For my six-point degree-five curve, the levels contain 6, 5, 4, 3, 2, and finally 1 point: the final red point lies on the curve. The green curve shows the full evaluation across many values of t.

Part 2: Bézier Surfaces with Separable 1D de Casteljau

A Bézier surface has two parameters, u and v, instead of the single parameter t used by a curve. I implemented the same interpolation step in 3D in BezierPatch::evaluateStep. The helper evaluate1D repeatedly reduces a row of control points to one 3D point. In BezierPatch::evaluate, I first evaluate each row at u, then evaluate the resulting set of row points at v. This separable approach yields one position on the patch.

Section II: Triangle Meshes and Half-Edge Data Structure

Part 3: Area-Weighted Vertex Normals

For each vertex, I traverse its incident faces using the half-edge rotation h = h->twin()->next(). For each non-boundary triangle with positions p0, p1, p2, I add cross(p1 − p0, p2 − p0) to the normal accumulator. The cross product points perpendicular to the face and its magnitude is twice the triangle area, so the sum naturally weights larger faces more heavily. I then normalize the accumulated vector.

On dae/teapot.dae, pressing Q switches from per-face normals to interpolated vertex normals. The geometry and wireframe stay the same, but lighting changes from faceted patches to smooth shading.

Part 4: Edge Flip

Edge flipping changes the diagonal shared by two adjacent triangles. The four surrounding vertices remain in place; the connectivity changes from the original diagonal to the one connecting the two opposite vertices. My HalfedgeMesh::flipEdge handles an interior edge in constant time. It obtains the six local halfedges and two faces, then rewires each halfedge's next, twin, vertex, edge, and face relationships and updates representative halfedge references. No elements are allocated or removed. Boundary edges are rejected.

Because the operation is topological, the most useful test was to select an interior diagonal, flip it, and compare the neighboring triangles with the camera unchanged. The chosen diagonal visibly switches direction without making a hole in the teapot.

Part 5: Edge Split

Splitting an interior edge inserts a vertex at the midpoint of its endpoints. Each of the two adjacent triangles is divided into two, giving four triangles total. My implementation allocates the new vertex and necessary faces, edges, and halfedges, reuses the original elements wherever possible, then assigns the connectivity for the four face cycles and all twin relationships. It also returns the new vertex, as required by the mesh editor. Like edge flipping, a key correctness check is that all incident vertices, edges, and faces have valid representative halfedges after the update.

Part 6: Loop Subdivision for Mesh Upsampling

Loop subdivision replaces each triangle with four smaller triangles while moving vertices toward a smoother surface. I used the three-stage approach: (1) compute all new positions from the original mesh, (2) split every original edge and flip only the newly added spokes connecting an old vertex to a new one, and (3) apply the precomputed positions. Saving the original edge list and using isNew flags prevents newly added edges from being split again in the same pass.

For an interior edge with endpoints A, B and opposite vertices C, D, the new edge-point position is 3/8(A+B) + 1/8(C+D). For an original vertex of valence n, the new position is (1 − n·u)P + u·Σ neighbors, where u = 3/16 for valence 3 and otherwise u = 3/(8n). Calculating these values before changing connectivity ensures every weight uses the coarse original neighborhood.

Repeated subdivision rounds sharp cube corners and smooths sharp edges, but the original face diagonals create uneven vertex valences. As a result, the unmodified cube becomes slightly asymmetric under repeated subdivision:

Original cube — repeated Loop subdivision

To improve the symmetry, I pre-split the diagonal across each of the cube's six square faces. This creates a face-center vertex and four triangles per original square face, giving a more balanced pattern before the same Loop subdivision operation. With more regular connectivity, the refined result is visibly rounder and more symmetric:

Cube with face-center splits — repeated Loop subdivision

This experiment illustrates that subdivision smoothness depends not only on the number of triangles, but also on the mesh's connectivity. Pre-splitting redistributes the irregularity of the original cube triangulation; it does not need to change the cube's initial visible silhouette.

Sharp-feature preservation by pre-splitting

To study how subdivision affects sharp features, I also used dae/icosahedron/input.dae. Without pre-processing, successive Loop subdivisions round off the pronounced top vertex and make the mesh more sphere-like. I then reloaded the original icosahedron and split each of the five edges incident to the top vertex before subdividing. This places a tighter ring of vertices around the tip. The pre-split version retains a more prominent top feature in the first and second iterations, illustrating how additional local connectivity can limit smoothing of a sharp feature.

These comparisons are qualitative: the camera view is kept similar, and the important evidence is the relative top profile and the concentration of small triangles near the tip.

Extra Credit — Boundary-Edge Splits and Boundary Loop Subdivision (Parts 5 and 6)

I extended splitEdge to accept an edge on an open mesh. Unlike an interior edge, a boundary edge borders only one real triangle; splitting it therefore adds one face while also updating the halfedges of the virtual boundary loop. The code preserves the boundary cycle and creates a midpoint vertex without closing the surface.

I also used boundary-specific subdivision weights: a new vertex on a boundary edge starts at the endpoints' midpoint, and an existing boundary vertex with two boundary neighbors moves to 3/4·P + 1/8·(P_left + P_right). Interior vertices retain the ordinary Loop weights. I tested both features on a square made of two triangles, first splitting an exterior edge and then running two successive Loop subdivisions. The mesh stays connected and its open border becomes smoother.

Extra Credit — √3 Subdivision for Triangle Meshes (Part 6)

As a separate subdivision method, I implemented √3 subdivision on closed, oriented triangular meshes, with R as the MeshEdit shortcut. Unlike Loop subdivision, which splits every original edge and creates four triangles per old triangle, a √3 step introduces one vertex at the centroid of every original triangle and rearranges connections across original edges. Each old triangle therefore contributes three new triangles, and repeated steps refine the mesh at a different rate from Loop subdivision.

I compute new positions for old vertices using their original one-ring neighborhoods. For a vertex of valence n, with original position P and neighbors Pi, the update is:

P' = (1 − αn)P + (αn/n) · ΣPi,   αn = [4 − 2 cos(2π/n)]/9.

I calculate the old-vertex updates and triangle centroids from the unmodified mesh, then construct the new face connectivity consistently, with each original edge replaced by the connection between its neighboring face centroids. This implementation leaves open meshes unchanged; boundary handling is shown separately for the Loop scheme above.

On dae/icosahedron/input.dae, pressing R repeatedly creates a denser and progressively rounder triangular mesh without visible holes. This is a separate algorithm and separate GUI shortcut from the required Loop subdivision on L.

Visual checks show stable repeated subdivision on this closed mesh; these screenshots do not by themselves establish correctness for every possible topology.

Final Notes

The most valuable checks were side-by-side geometric comparisons: a control-point edit demonstrated the effect on a Bézier curve; the shading toggle isolated normals from geometry; edge flipping and splitting showed local changes to half-edge connectivity; and cube subdivision made the relationship between connectivity and smoothness visible. An early attempt to load the open test square also failed because the input DAE listed unused vertex positions; correcting the test mesh allowed the boundary algorithms to be exercised in MeshEdit. After these changes, the required scenarios, open-boundary tests, and the additional √3 subdivision test on a closed mesh rendered without visible holes.
